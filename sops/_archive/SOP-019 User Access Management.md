# SOP-019 — User Access Management

1 PURPOSE
This Standard Operating Procedure (SOP) describes procedures for granting, modifying, periodically
reviewing, and revoking access to all Netramind employees and contractors requiring access to
Netramind GxP regulated systems and applications, to prevent unauthorized access to the
Netramind’s systems and data collection tools (DATs).
2 SCOPE
This procedure applies to all Netramind employees, contractors, and consultants who require access
to GxP systems and applications, including internally managed and externally hosted systems used in
clinical trial activities.

4 DEFINITIONS
4.1 Access Control— A process that limits and controls access to resources of a computer system.
4.2 Active Directory— A Microsoft product that consists of several services that run on Windows
Server to manage permissions and access to networked resources. Active Directory stores data
as objects. An object is a single element, such as a user, group, application, or device, such as a
printer.
4.3 Audit Trail— Metadata records that allow the appropriate evaluation of the course of events by
capturing details on actions (manual or automated) performed relating to information and data
collection and, where applicable, to activities in computerized systems. The audit trail should
show activities, initial entry and changes to data fields or records, by whom, when and, where
applicable, why. In computerized systems, the audit trail should be secure, computer-generated
and time stamped.
4.4 Metadata— The contextual information required to understand a given data element. Metadata
is structured information that describes, explains, or otherwise makes it easier to retrieve, use or
manage data. Relevant metadata are those needed to allow the appropriate evaluation of the
trial conduct.
4.5 Users—Netramind employees, consultants, and contract employees who access the systems and
applications.
5 RESPONSIBILITIES
5.1 Human Resource (HR) or Designee
5.1.1 Notify IT and FAM when a new user requires a Netramind account, an existing user is
transferred from one department to another that impacts their assignments, and an
existing user is terminating their association with Netramind.
5.2 Functional Area Managers (FAM) or Designee
5.2.1 Complete FRM-019-01 User Access Form for all new employees, transferring and
terminating employees within their department.
5.2.2 Ensure access requests align with user job responsibilities.
5.2.3 Notify IT when their functional area / department are engaging consultants or temporary
contract staff who need access to Netramind’s systems and applications.
5.2.4 Approve access to systems and applications as well as shared folders for their functional
area.
5.3 Information Technology (IT) or Designee
5.3.1 Responsible for granting, transferring, and revoking access based on request from
FAM/Designee.
5.3.2 Maintain access related documentation in the IT files.
5.3.3 Ensure access is provisioned based on least privilege principles and role-based access.
6 PROCEDURE
6.1 Raising a request for new employees, transfer, or termination of an existing employee.
6.1.1 Requests for new access, changes to access, or termination of access must be initiated by
HR or the Functional Area Manager and communicated to IT.
6.1.2 The communication will include at a minimum:
• Name of employee
• Job Title
• Functional Area / Department (Current and new in case of transfer)
• Start date (new or transfer) and stop date (existing)
• Services required (default services e.g., MS Outlook, MS Office, and Internet
access etc.)
• Relevant GxP systems for employees to perform tasks according to their specific
roles and responsibilities, e.g., reviewer, approver, etc.
6.1.3 Employees who require access to data owned by another department require the
approval of the FAM/Designee of that department.
6.1.4 Once the notification from HR is received, the FAM/Designee completes FRM-019-01
User Access Form and forwards it to IT Help Desk.
6.1.5 IT provides access to the systems only when the procedure is completed.
6.1.6 Each user is given a copy to sign indicating they have understood the conditions of access.
6.1.7 Completed User Access Forms are maintained within the IT files in a folder named “User
Access.”
6.1.8 Following the receipt of notification for user access, the IT Department will acknowledge
the receipt to the FAM/Designee.
6.1.9 The user credentials for network access will be securely delivered to the user.
6.1.10 Account terminations involve the archiving of any user generated data and audit logs for
that account. Once all the data has been archived, the account is then deleted. IT
completes the account archiving and deletion activity promptly upon notification,
typically within two (2) business days, of receiving the notification of employee
termination.
6.2 Modifying User Access Privileges
6.2.1 FAM/Designee ensures that when an employee from their functional area / department
changes role within the organization, their access is amended so that it reflects the
requirement of their new role. Any user privileges that are no longer required for the
employee’s new role are removed.
6.2.2 The FAM/Designee completes FRM-019-01 User Access Form to request IT for changes to
an employee’s user access privileges for any Netramind’s systems and applications.
6.3 Periodic Review of User Access
6.3.1 User access reviews must be conducted periodically based on system risk, at least
annually, and more frequently for high-risk systems.
6.3.1.1 The review will be conducted as follows:
• IT will generate a list of users by application.
• The list is sent to each FAM/Designee for confirmation that all users
identified are authorized to use the system.
• Access for any unverified or unauthorized user must be removed or
investigated.
• IT maintains a file of this list and updates it periodically.
6.3.2 The FAM/Designee is responsible for conducting annual user access reviews of file
permissions within their department’s shared network drive.
6.3.3 User access reviews should be documented and retained for auditing purposes.
6.3.4 If inappropriate or unapproved changes to user access for a Netramind system is
identified as part of user access reviews, a deviation should be documented, and
appropriate corrective actions should be implemented.
6.4 Periodic Review of Identification (ID) Codes and Passwords
6.4.1 IT is responsible for ensuring uniqueness of ID and Passwords
• Deactivate all users upon leaving Netramind.
• Ensure the system does not permit creation of users with the same credentials.
6.4.1.1 IT performs periodic Review of ID Codes and Passwords
• Password change requirements are defined by procedure or by a system capable of
enforcing changes.
6.5 Access to External Systems and Applications
6.5.1 If Netramind is utilizing CSP’s systems and applications, Netramind ensures that access
controls for external systems are appropriate, either through CSP procedures or internal
oversight.
6.5.2 In such cases, the FAM/Designee is responsible for coordinating with the Project Manager
/ Designee and IT from the CSP for requesting, maintaining, and revoking access to their
systems and applications.
6.5.3 The FAM/Designee is responsible for performing periodic review of user access on an
annual basis along with CSP’s PM. All such reviews are to be documented, and corrective
action are implemented when discrepancies are noted.
