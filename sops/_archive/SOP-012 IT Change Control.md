# SOP-012 — IT Change Control

1 PURPOSE
This Standard Operating Procedure (SOP) outlines the process for requesting and managing changes
to computerized systems utilized by Netramind for GxP activities.
2 SCOPE
This procedure applies to significant changes made to controlled or production computerized systems
used in support of GxP-regulated activities.
3 REFERENCES

• SOP-004 GxP Records Retention

4 DEFINITIONS
4.1 Change Control—Change Control is a general term describing the process of managing
how changes are introduced into a controlled system.
4.2 Change Control Form (CCF)— An official request for prospective approval to implement
a change to a validated system.
Change Record—Documentation associated with a proposed and implemented change to a
controlled computerized system.
5 RESPONSIBILITIES
5.1 IT Manager or Designee
5.1.1 A Change Originator initiates the change control and provides justification for the
Change. The IT Manager / Designee ensures that changes made to computer
systems, for which they are responsible, follow this change control procedure.
5.1.2 Authorize the testing and implementation of the change.
5.1.3 Ensure change control is closed prior to production use.
5.1.4 Arrange downtime requirements to implement the changes in production.
5.2 Change Control Coordinator or Designee
5.2.1 Manages review and approval of the change control with appropriate signatures.
5.3 IT Quality Assurance (QA) or Designee
5.3.1 QA is responsible for review and approval of the impact assessment and oversight
of the change operation.
6 PROCEDURE
6.1 Information Technology (IT) Change Control Process
6.1.1 The IT Change Control process is used to manage significant changes to controlled
or production computerized systems supporting GxP activities.
The change control is documented appropriately using FRM-012-01 IT Change Control
Form.
6.1.2 The IT Manager / Designee ensures that the changes are deployed to the
production environment and that there is minimum disruption to the services.
6.1.3 The individual initiating the change documents the proposed change and
associated justification.
6.1.4 The Change Request Form contains:
6.1.4.1 Change NO—A unique change control number must be filled in. QA
should be contacted to get change control registered and for the Unique
Change Control number.
6.1.4.2 Change Originator / Department
6.1.4.3 Date of Request
6.1.4.4 Application Name—The name of the application that requires the change
should be documented.
6.1.4.5 Change Type—One of the following must be selected:
•
• Standard: This should be checked when the change is according to a pre-
arranged schedule of a change window and such changes could be
recurring types.
• Emergency change: An emergency change is used in response to a system
failure that impacts personal safety. GxP compliance and/or critical
business operations. Emergency changes require expedited review and
approval as appropriate prior to implementation where feasible
6.1.4.6 A detailed description of the change and justification for change
6.1.4.7 Change Implementation Plan
6.1.4.8 A detailed back-out plan for unsuccessful attempts to implement the
changes
6.1.4.9 Schedule of the implementation
6.1.4.10Environment location—All the environments where the change will be
implemented will be documented in this section
6.1.4.11Impact of the change—Originator documents the impact of change and
sends it for review
6.1.4.12Impact Assessments may consider:
• System functionality, security, and data integrity
• Interfaces
• Validation status
• User impact
6.1.4.13CCRB Review and Approval
6.1.4.14Change Request Status
6.1.4.15Verification that the change was successfully implemented
6.1.4.16Requestor and approver sign-off

6.1.6 Approved changes are implemented according to a documented implementation
approach that may include testing, deployment, rollback considerations, and
documentation updates where applicable.
6.1.7 Once the implementation plan has been created, the IT Manager ensures that:
• Confirm that documents, SOP’s, forms, etc. impacted by the change have been
revised and approved.
• Relevant SOPs, documentation, and training materials are updated where
appropriate.
6.1.8 QA reviews significant changes to ensure appropriate documentation, testing, and
approvals are completed prior to closure.
6.1.9 All the forms and change control related documentation is filed as per the SOP-004
GxP Records Retention.
